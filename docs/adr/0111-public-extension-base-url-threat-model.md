# Public Extension Base URL Threat Model

Status: accepted

Any public Extension Base URL is reachable by more than Cursor. V1 should treat the generated local API key as the only Cursor-facing credential required for OpenAI-compatible endpoints, while keeping unauthenticated endpoints extremely small.

## Consequences

- `/health` is unauthenticated but returns only minimal liveness, such as `{ "status": "ok" }`.
- `/ready`, `/v1/models`, `/v1/chat/completions`, Usage Statistics endpoints, status endpoints, and internal endpoints require either the generated local API key or the separate internal control secret where appropriate.
- Failed authentication returns generic `401` or `403` responses without account state, model lists, quota state, local paths, tunnel details, setup state, or runtime diagnostics.
- The generated local API key should be high entropy, generated by the extension, stored in `SecretStorage`, user-regenerable, and never logged, exported, synced, or reused for internal extension-control authority.
- The internal control secret remains separate from the generated local API key. The Cursor-facing key must not grant access to extension-authority operations.
- V1 should include basic abuse protection on public-facing endpoints: bounded request body size, sane streaming/request timeouts, authentication-failure rate limiting, and structured safe logs.
- Public URL threat modeling applies equally to durable user-owned URLs and temporary Quick Tunnel URLs.
- Doctor/support output should report the posture without exposing the generated local API key, internal control secret, tunnel credentials, raw prompts, raw responses, or raw account identity.
